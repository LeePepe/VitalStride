# 设计评审结果

**总分：28 / 35** — 本轮已形成清楚、紧凑的训练工作区；推荐 C 全计划矩阵继续打磨，A 保留作历史对照方案，B 暂不作为首选。此评分针对 V2 当前截图，旧版 31/35、30/35 均未沿用。

评审对象为统一 blue/slate 主题下的三种布局。主题与布局分开判断；明暗适配不算两套布局。当前截图未发现需要阻止方案比较的 P0 视觉硬伤，但仍有触控宽度、编辑上下文和字体细节需修正。这是设计方案评审，不是生产发布验收。

## 必修项（P0）

**当前版本无 P0 视觉硬伤。** 首轮查看的 `table-picker-empty-{light,dark}.png` 曾出现黄色禁止占位；末轮重新打开两张当前文件，已确认消失，不再作为未解决 finding。无结果页保留底部搜索清除键与 Filter 恢复入口。

## 建议项（P1）

坐标均为逻辑 pt，原点在屏幕左上；393pt 图为 786px 宽，375pt 图为 750px 宽。

1. **撤销目标需补齐宽度。** `table-keyboard-undo-light.png` 右侧状态槽约 `(349…381, 450…494)` 的“撤销”视觉文字窄。有限源码核对发现 `CompactStatusLine` 的该按钮只有 `minHeight: 44`，没有最小宽度，也没有扩大的矩形命中区。建议给标签 **minWidth: 44、minHeight: 44、矩形 contentShape**；同样检查 RPE 的“不设置”等短文本动作。截图只证明看得到，未进行实际命中测试。

2. **休息/撤销期间，输入对象不应只靠高亮行推断。** `table-keyboard-rest-light.png` 的 `(0…393, 450…494)` 状态槽只剩计时与休息操作；`*-keyboard-undo-*` 同位置只剩删除反馈。当前 fixture 中第三组仍可见，因此没有遮挡故障；但滚动后键盘本身没有动作名/组号。建议在现有字段条加一行或一处 **11–12pt「平板卧推 · 组3」**，优先复用字段条左侧/现有草稿提示，不额外增加第二个状态条。A/B 当前行再加 **2pt 蓝色起始标记或编辑符号**，避免深色只靠底色识别选择。

3. **组类型 9pt 过小。** A/B 的组号下方“热身/正式”（例如 `table-keyboard-light-large-narrow.png`，`x=20…44, y=230…360`）可见但吃力；源码明确为 9pt。建议 **11pt**，保持现有 **44×48pt** 组号目标，使用两行与 1–2pt 行间距，不缩小点击区换密度。

4. **B 的密度收益不足。** `rail-normal-light.png` 右栏约 `(76…381, 408…732)` 为空白，同时让出 64pt 给动作栏并省掉历史列。切动作路径稳定是真实优点，但本次只有四个动作，常态信息量低于 C。建议不作为默认；若继续发展，利用这一区域放 **紧接当前动作的下一动作紧凑预览，行高 48pt**，不要加装饰卡片填空。A 的动作标签与下方队列也有导航重复，可后续比较只保留一处后的密度。

5. **More 的动作性质还可以更直观。** `table-more-light.png` 当前组的删除（约 `y=462…506`）和整次训练的结束（约 `y=754…798`）与普通导航同色、同右箭头。建议删除使用语义红色图标/文字，结束文案写为 **“结束训练…”**，保持 **≥44pt** 行高与二次确认。动作范围的三段分组应保留。

## 布局建议

| 顺位 | 布局 | 本轮判断 |
|---|---|---|
| 1 | **C 全计划组矩阵** | `matrix-normal-light.png` 在约 `y=92…556` 展示四个动作、16组，实际密度最高；选中单元格有边框与编辑符号，任意组的编辑入口直观。键盘打开时前12组可见、第四动作在下方滚动，属于合理的视口取舍。适合作为本次紧凑需求的主方向。 |
| 2 | **A 当前动作表格** | 上次、重量、次数、完成在一行，适合逐组录入和历史比较。当前组3在所有提供的键盘状态中都可见。代价是只展示当前动作四组明细，跨动作需切换。 |
| 3 | **B 侧栏工作台** | 64pt 导航位置固定，切动作明确；常态只显示四组且留白最多，右侧没有历史列。更适合动作很多或宽屏的进一步研究。 |

动作选择页保留 **64pt 分区侧栏＋双列** 是正确方向。393pt 截图中卡片至少76pt高，去掉巨型图标后十个动作在当前视口内可扫完；搜索/Filter、取消/已选/添加集中在两行底栏。源码有限核对显示侧栏点击是滚动到分区，未变成器械过滤。截图没有实际点击，不能据此证明滚动位置追踪、输入焦点或跨筛选选择行为。

## 做得好的地方（保留）

- 头部64pt只提供训练概况；完成训练移入 More，不与完成当前组竞争。
- 44pt状态槽在 none/rest/undo 间保持高度；三种布局的六种状态均未发现键盘遮住当前 fixture 组或底部主按钮。
- 键盘只留下重量、次数、辅助键、输入区和提交；RPE用原188pt数字区替换，没有把整页继续顶高。`table-rpe-{light,dark}.png` 中选择8清楚，主按钮仍在原位。
- More 的组/动作/整次训练三段责任清楚，复制明确提示覆盖已有输入，减少范围误解。
- 明暗主题的数据密度和区域顺序一致，矩阵深色仍保留边框与非颜色的编辑/完成符号。
