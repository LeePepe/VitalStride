# V2 紧凑布局交付

**[打开最新布局画廊](index.html)** · 2026-10-16 · my-designer 主导

主题色独立。本轮用一套 DesignKit blue/slate 比较三个训练布局，共用同一套底部操作和键盘。旧 3×3 风格矩阵已退出布局选型，旧评分不适用于 V2。

## 先比较什么

| 方案 | 最适合 | 要接受的代价 |
|---|---|---|
| **A 当前动作表格（逐组对照）** | 沿用当前记组习惯；重量、次数、上次、完成横向对齐 | 跨动作查看需切换；顶端标签和下方队列同时提供导航 |
| B 侧栏工作台 | 频繁切动作，固定动作位置 | 窄屏省去上次列，历史值进入键盘辅助；只看当前动作时下部留白 |
| C 全计划组矩阵（主推紧凑方向） | 一眼扫全计划；演示的 4 动作 16 组可同时看到 | 每格只展示核心值；上次 / 类型 / RPE 进入输入和 More |

键盘底部固定显示动作短名与组号，休息 / 撤销期间仍能辨认输入对象。A/B 当前组增加 2pt 起始标记。普通组行 52pt，重量 / 次数点击区 48pt 高，编号至少 44pt 宽；头部 64pt，固定状态槽 44pt。密度来自去掉大卡、重复概览和说明占位，不靠缩小触控目标。

## 区域和行为

完整表见 [区域职责](north-star.md)。头部只看训练状态；导航选动作；组表或矩阵选任意主组；状态槽显示当前组、休息或撤销；底部只留 More、加组、完成当前组。

- **输入**：点重量 / 次数打开并全选；切字段保留两份草稿。收键盘保存，不记组。有效草稿切动作先保存，无效草稿阻止切换。
- **记组**：输入区“保存并记组”提交当前组并启动休息；编辑已完成组时变成“保存修改”。主页面勾和底部完成均作用于明确选中组。
- **扩展输入**：上次、复制下组、RPE、组类型、More。RPE / 类型替换固定 188pt 数字区，随草稿保存或放弃；不增加键盘高度。
- **More**：当前组（类型 / RPE / 复制 / 删除）、当前动作（加组 / 替换 / 高级）、整次训练（加动作 / 结束）。结束需确认；删除可撤销；撤销优先显示，休息继续。
- **动作选择**：64pt 固定器械侧栏用于分区跳转；普通字号两列。搜索、Filter、已选顺序清单、取消、确认都在底部；大字号允许单列回退。无结果保留原搜索框和滚动宿主。

单侧、子组、AI 替代、动作排序 / 删除、放弃训练的生产功能入口已在高级说明中分配，未接入此演示原型。当前原型只操作 fixture，不写训练数据库。

评审后的取舍：主推 C 继续验证紧凑全览，A 保留逐组历史对照；B 作为固定导航研究，不作默认。B 当前动作结束后的留白是已披露的 P1，不用装饰卡填充。

## 性能结论

原型保留 200ms 搜索防抖并缓存分组；选择 / 反选不重算搜索。数字输入只改草稿，提交才改 fixture；计时只更新状态子视图。运行时采用单层 lazy 滚动容器。

[生产源码审计](../RedesignEvidence/compact-performance-audit.md) 找到三个优先方向：历史提示与渐进建议重复查询、键盘 context 未变仍赋值 rootView、统计重复遍历 / 排序。每键或单组完成路径没有直接同步 `modelContext.save()`，不能把卡顿归因于“每键写盘”。

这些是源码证据与待测路径。**本轮未修改生产性能代码，也未跑 Instruments，不能认定卡顿已修复。** 审计内给出了后续修复的计数与延迟验收建议。
