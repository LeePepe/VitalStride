# 动作选择 × 训练：设计目标

2026-10-16 · my-designer 主导 · Native SwiftUI / DesignKit · 明确的演示数据。

## 产品方向

抬眼知道下一步，拇指完成一次记录。选动作优先识别与连续选择；训练优先当前组与上次记录。
参考 Apple Fitness 的状态识别、Strong/Hevy 的连续记组和 Apple Reminders 的列表密度；不复制其品牌。

风格不改变数据与操作；布局不改变功能语义。3×3 组合均给动作选择、训练的 light/dark 原生截图。

## 可检查规则

- iPhone 393×852pt；横向内边距 20pt；8/12/16/20/24/32 间距；单列列表行不低于 64pt。
- 触控目标 ≥44×44pt；主按钮高 52pt；数字输入区域 ≥56pt。图标带 VoiceOver 名称，装饰隐藏。
- 至少标题/正文/辅助三档。组内数值等宽，单位与表头明确，完成同时显示 check + 文本。
- 常规正文 16pt，辅助正文最低 12pt；accessibility1 改用单列、纵向字段、可滚动区域，不缩小字挤入卡片。
- 只用 `theme.primary` / `theme.neutrals` / 固定语义色。主正文用 text1，辅助用 text2。
- 无照片、无动画背景、无整页模糊、无重复大图标占位；平面亮度层级 + 0.5pt 边框。
- 主按钮只负责当前阶段操作。结束训练独立入口、二次确认；删除可撤销。
- 搜索及筛选不丢已选；已选有顺序和总数；清空筛选入口明确；空库与无搜索结果分开。
- 记组后展示休息，休息支持 ±10秒/跳过；编辑与休息不可遮挡；下一动作可主动切换。
- 计时只更新局部视图；生产迁移保留日期差值、搜索 debounce、稳定 ID、惰性列表和现有缓存。
- 演示不是落地性能结论：本轮记录构建/导出与行为测试；真实搜索延迟、帧率和能耗必须另测。

## 评审门

独立 design-reviewer 按 spacing / typography / color / hierarchy / grouping / visualization /
platform 七项各 5 分；操作型界面 visualization 指完成进度与休息进度，不为达分加无关图表。
提供实际渲染图 + 本文，修复 P0，披露 P1。macOS ImageRenderer 的手机尺寸截图不冒充 iOS 模拟器验收。
最终生产迁移仍须 iPhone Simulator light/dark + Dynamic Type、键盘和 VoiceOver 验收。
